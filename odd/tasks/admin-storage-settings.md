# Admin-Configurable AWS S3 Storage
Objective: Let the system administrator select MinIO or AWS S3 for new meeting uploads while preserving access to existing MinIO-backed meetings.
Branch: `feature/admin-storage-settings` · Delivery: `chain_strategy=feature-branch-chain`; user authorized release/deploy after implementation and checks (2026-10-17) · Checks: backend `uv run pytest`; frontend-2 has no test script, release build is applicable.

## Specs

### S1 — Configure global storage from the web UI
User request: “upa, entonces si es eso, porfa, agrega configuración global como admin, de poder seleccionar el almacenameinto, es que quiero configurar un s3 de aws desde la ui web”
Acceptance: The system superuser can select MinIO or AWS S3 from the global admin UI and configure the AWS bucket, region, access key ID, and secret access key. The selected provider is used for new uploads.

### S2 — Preserve existing MinIO objects when switching
Selected choice: “Conservar MinIO para lo existente (recomendado)” — “Las nuevas subidas van a S3 y los archivos actuales siguen leyéndose de MinIO; requiere guardar el proveedor por reunión, sin copiar datos.”
Acceptance: Existing meeting objects remain on and are read from MinIO; new meetings record the currently selected provider. Reads, processing/reprocessing, and deletion use each meeting’s provider. Do not bulk-copy existing objects.

### S3 — Protect global storage credentials
User request includes: “como admin” and “desde la ui web”.
Acceptance: Only system superusers can read or update global storage configuration. Persist the S3 secret key encrypted using the existing token-encryption pattern; never return its plaintext to the browser. Keep all new credential handling server-side. An empty or whitespace-only secret field preserves the stored value, and the UI must say that leaving it blank keeps the current secret.
